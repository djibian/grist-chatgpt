# J2 Design Compression Review

Status: **proposal for scope decision, not a new accepted J2 contract**. No product code is changed by this review.

Audited GitHub `main` `530b75662d622dac9b39e0e395ba9b0c3dcab575` on 2026-09-25. The only open PR at the final review check was #158, ready, exact head `4bf1f3a9f9990b91278a24d1b26c4efc9ee3bcb8`, with green CI. The review records a `CHANGES REQUIRED` product-scope finding on that head. Recheck these mutable facts before acting on this proposal.

## Decision and evidence boundary

**Compress J2 around one real transformation.** The present sequence implements test machinery before it implements the Builder's schema/UI transformation. On `main`, the J2-specific observer, manifest, provisioner, isolation probe, browser-verifier core and two operator commands total about 2,600 lines, excluding tests. PR #158 adds roughly 1,200 more lines, including a private Chromium DevTools transport. No J1-backed J2 schema/UI dispatcher is integrated. This is a prioritization and proof-design finding, not a claim that every existing component is defective.

The currently connected `J2-stage-tracking-fixture` has the **date already present**, empty teacher LinkKeys and an observed successful model-facing `Enseignants` read. Its ACL parity, teacher-browser behavior and the actual Builder transformation have not been proved. The J2 synthetic provisioner requires `Date_du_contact` to exist and writes its own five ACL resources/thirteen rules into a pristine fixture. A browser pass on that policy would test the newly invented policy; it would not demonstrate that the existing reference policy was preserved. The current oracle's date-absent and managed-rerun objects describe expected states, but the tests of those objects do not execute the transformation on Grist.

The product vision already supplies the needed boundaries: a fixed accepted business oracle, exact managed scope, bounded effects through J1, no blind replay, no false concurrency claim, and browser evidence for client-only `user.LinkKey`. Grist documents `user.LinkKey` as available to the web client but not the API ([Grist access rules](https://support.getgrist.com/access-rules/)). An owner/API read cannot replace a teacher browser check. The vision's *typical* invalid/revoked-key examples do not oblige this date-addition scenario to build a general LinkKey lifecycle test system.

## Component decisions

`KEEP` means **ESSENTIAL TO J2 PROOF**; `SIMPLIFY` means **USEFUL BUT SIMPLIFIABLE**; `DEFER` means **A LATER TRANCHE**; `REMOVE` means **OVER-ENGINEERED / REMOVE FROM THE J2 PATH**. "Remove" concerns the J2 obligation or implementation after a safe migration, never the confidentiality invariant it was meant to protect.

## Smallest J2 that answers the product question

One exact application binding and a disposable, sanitized **realistic copy**; one accepted change request to put `Date_du_contact` in the existing Stage follow-up flow; one bounded, recorded plan produced from observation; J1-backed schema/UI transformation on a date-absent initial checkpoint; separate adoption/reconciliation on a date-present, human-edited **initial** checkpoint; a true rerun on an already managed result; before/after snapshots of relevant data, UI, ACL/share/link facts; one small browser A/B/no-key access smoke on the same policy; and targeted lost-response, restart and conflict cases. A J2 run with an unknown affected access or overwrite guarantee suspends. No general ACL writer, test-platform API, cross-document permission engine or production credential lifecycle is required.

**Separate claims:** a pass on a controlled copy establishes this Builder capability for that copy, Grist version and bound policy. A claim about the live DINUM/reference document additionally requires an authorized, relevant policy/UI comparison (and live browser evidence only for a property that cannot be transferred or inferred from that comparison). Unknown reference parity remains explicitly `UNKNOWN`; it is not silently promoted by a synthetic pass. The live document containing pupils is never used for destructive, recovery or token-rotation tests.

## Minimal proof protocol

1. **Bind and protect.** With owner authority, observe just the touched schema/UI, records, assignment, relevant ACL/share/link dependencies and target Grist version. Prepare one sanitary controlled application with two independently prepared initial checkpoints; one lacks the date, the other already has a human-created date plus unrelated human layout/data edits. Confirm reference parity for relevant dependencies or record exactly which reference-specific claims remain unknown. Ensure the application is unreachable from model-facing reads throughout any test-token lifetime; the currently connected readable fixture cannot receive tokens.
2. **Baseline.** Independently freeze the business oracle. Snapshot stable row identities and protected data, relevant policy/UI state, expected date absence and human-owned layout. Test A positive, B negative including Raw Data and no-key negative in fresh non-owner browser contexts. If any critical baseline is unknown, do not assert policy-preserving delivery.
3. **Actually transform.** Have the Builder observe the state and produce an exact plan: add one Date column if absent, expose it in the existing teacher widget if absent, leave `Suivi_par`, rows and ACLs untouched **when the observed policy covers the new field**. Use J1 for authority, journal, preconditions, effects and exact post-read; refuse any unsafe intermediate exposure or overwrite. If the actual policy demands ACL writing, explicitly review and authorize that *necessary* effect separately; do not automatically install a new policy for the test.
4. **Verify and reconcile.** Compare stable identities and relevant business data, field count/type, field mapping, layout and access-policy facts; repeat the A/B/no-key browser checks, including an authorized date edit and forbidden access. Restore the independently prepared date-present/human-edited checkpoint and run the *same* intent as its **first** Builder run: adopt the existing field and preserve the edits. Then rerun on a managed result: no duplicated field/widget/record, and human changes persist or a documented conflict suspends.
5. **Exercise failure once per class.** Inject a lost response after a potentially applied schema/UI effect and a process restart; reconcile from the journal and live state without blind replay. Inject one concurrent human layout edit between observation and write; prove a real guard/isolation or suspension, never claim protection from post-write equality alone. Record `VERIFIED`, `VIOLATED` or `UNKNOWN` with target, contract, relevant revision, method, identity, time and affected dependencies. Clean tokens and verify cleanup before ending the controlled window.

## Proposed documentation edits and work sequence

This review does **not** silently alter the currently accepted BehavioralContract or merge a feature PR. A follow-up **documentation-only scope PR** should make these exact normative changes before additional J2 feature integration:

1. In `docs/ROADMAP.md`, replace the current J2-A → J2-B → J2-C → J2-D prerequisite chain with four finite deliverables: **(i)** relevant reference binding and one safe copy, **(ii)** actual J1-backed bounded transformation on date-absent and date-present/human-edited states, **(iii)** targeted browser regression on the affected teacher path before/after, **(iv)** interruption/concurrency/rerun and integrated independent review. Allow (ii) to be implemented in a protected copy while (iii) is prepared, but never declare J2 delivered with affected critical access `UNKNOWN`.
2. Replace the roadmap's unconditional static `DENIED` and `GRIST_ALLOWED_*` gate with the invariant that no secret-bearing fixture is readable by the model-facing bridge during its test window. List two acceptable implementations: separate origin without the bridge, or same-origin controlled exclusive window with strongest-path negative reads, stable configuration and verified key cleanup. A momentary 403 or unknown error is not evidence. The currently connected `READABLE` fixture remains barred from receiving keys.
3. In `docs/BEHAVIORAL-CONTRACT-STAGE-TRACKING.md` §§7–9, 14–17 and 20, preserve one trace/no reassignment, safe intermediates, concurrency and J1 recovery; collapse overlapping BROW-A/F/G into one positive flow, BROW-B plus Raw Data into one negative flow, and BROW-C into a short no-key/invalid control. Mark BROW-D/revocation as a separate unverified application property unless the transformation changes that dependency; narrow alternate-view and relation-tampering checks to the affected closure. Do not record `VERIFIED` for untested broader rights.
4. Keep `docs/J2-STAGE-TRACKING-ACCEPTED-SEMANTICS.md`'s business decision intact; distinguish *accepted application expectations* from properties this transformation actually impacts and can prove. Update `docs/J2-STAGE-TRACKING-REFERENCE-BINDING.md` and current J2 fixture/browser/isolation documents so they no longer describe the old A/B/C/D chain as a mandatory implementation path. Preserve their historical evidence and label unused code as diagnostic/deferred, not as proven reference behavior.
5. `docs/PRODUCT_VISION.md` needs **no new architecture**. At most clarify in its LinkKey section that its listed invalid/revoked scenarios are risk-dependent examples; J2's specific exit test is set by the impacted property closure. Keep its binding, browser-only semantics, execution and security invariants unchanged.

Recommended implementation order after the scope PR: run owner-authorized relevant binding and create the safe realistic copy; implement the small Builder planning/schema/UI dispatcher through J1; run date-absent → human-modified date-present → rerun plus fault/concurrency tests; then implement only the browser smoke actually needed to close impacted access claims; perform an independent exact-main J2 completion review. A missing reference authority or a real access-policy mismatch is a named gate, not a reason to build a new test platform.

**PR disposition:** #156 is already integrated; its verifier core should not become the J2 delivery gate. Leave it dormant while replacing/retiring its scenario scaffolding after the narrower proof is operational. #158 is open and ready but should **not merge in its present scope**: its current date-present-only command and custom Chromium transport reinforce the wrong prerequisite, and neither it nor its green CI proves a transformation or reference-policy parity. Salvage only a bounded, tested teacher browser path if it is the smallest solution; otherwise close #158 as a superseded experiment. The integrated AccessModel observer may remain an internal read-only diagnostic; the synthetic ACL writer and HMAC isolation stack should not drive J2 completion and can be retired once no legitimate caller depends on them.
